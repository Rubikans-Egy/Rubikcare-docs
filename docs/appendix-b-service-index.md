## 🚫 8. ⚠️ الخدمات والأنماط المحظورة (Forbidden Patterns)

ممنوع تماماً استخدام الأنماط التالية في أي صفحة أو خدمة **جديدة**:

| النمط المحظور | السبب | البديل الصحيح |
|---------------|-------|----------------|
| `@inject BusinessDbContext` مباشرة في صفحة Blazor | يكسر مبدأ فصل الاهتمامات، ويسبب أخطاء "A second operation started". | استخدم `DbContextFactoryService` أو `IGenericService<T>`. |
| كتابة منطق أعمال (Business Logic) داخل `Controllers` | الـ Controllers مخصصة للتنسيق (Orchestration) فقط. | انقل المنطق إلى `UseCase` في طبقة `Application`. |
| استدعاء `Infrastructure` (مثل Repositories) مباشرة من `Web` أو `Mobile` | يكسر تبعية الطبقات (Dependency Rule). | استخدم `UseCase` أو `ApiService` (للموبايل). |
| وضع **صفحات كاملة** (مثل `Dashboard.razor`) في `Shared.UI` | يسبب مشاكل أداء في MAUI ويكسر مبدأ المسؤولية الواحدة. | ضع **المكونات فقط** (Components) في `Shared.UI`. |
| استخدام `IMemoryCache` بشكل مباشر ومتفرق في الخدمات | يؤدي إلى بيانات قديمة (Stale Data) وصعوبة في المسح. | استخدم `UserSessionService` كمصدر وحيد للكاش. |
| إرجاع `Entity` مباشرة من API | يعرض بيانات حساسة غير مقصودة ويكسر التجريد. | استخدم `DTO` (Data Transfer Object) دائماً. |

## 9. ⚠️ ملاحظة معمارية هامة: فخ التتبع في GenericService (Tracking Pitfall)

### المشكلة
عند استخدام `IGenericService<T>` للقيام بعملية "جلب كيان" (`GetByIdAsync` أو `GetAllAsync`) ثم "تعديله" ثم "حفظه" (`SaveChangesAsync`) بشكل منفصل، قد تفشل عملية الحفظ بصمت وتُرجع `0` صفوف متأثرة، حتى لو لم يحدث استثناء (Exception).

### السبب الجذري
تعتمد `GenericService` على `IDbContextFactoryService` الذي ينشئ `DbContext` جديدًا ومعزولًا لكل عملية:
1. `GetByIdAsync` يفتح سياقًا (أ)، ويجلب الكيان.
2. عند الخروج من الدالة، يُتلف السياق (أ)، ويصبح الكيان **غير متتبع (Detached)**.
3. عند استدعاء `SaveChangesAsync` لاحقًا، يفتح سياقًا (ب) جديدًا فارغًا. بما أن الكيان غير متتبع في السياق (ب)، فإن `ChangeTracker` لا يرى أي تعديلات، فيُرجع `0`.

### الحل المعتمد معمارياً
لعمليات التحديث المعقدة التي تتطلب جلب كيان وتعديله وحفظه، **يجب** استخدام أحد النهجين:

**النهج 1 (الموصى به للعمليات الحساسة):** استخدام `ExecuteUpdateAsync` (إذا كان مدعوماً في إصدار EF Core) لتنفيذ تحديث مباشر يتجاوز `ChangeTracker`.

**النهج 2 (البديل الآمن):** حقن `IDbContextFactoryService` مباشرة داخل الـ `UseCase` وتنفيذ الجلب والتعديل والحفظ داخل دالة `ExecuteWithNewContextAsync` واحدة، لضمان بقاء الكيان متتبعاً (Tracked) طوال دورة حياة العملية:

```csharp
// ✅ مثال صحيح داخل UseCase
var result = await _dbFactory.ExecuteWithNewContextAsync(async context =>
{
    var dbContext = (DbContext)context;
    var entity = await dbContext.Set<MyEntity>().FindAsync(id); // Tracked
    if (entity == null) return 0;
    
    entity.Status = "NewStatus"; // ChangeTracker يلتقط هذا
    return await dbContext.SaveChangesAsync(); // سيُرجع 1 بنجاح
});
```

# فيما يلي الآليات الثلاث المعتمدة لتحقيق فكرة "الماستر كي" بأعلى درجات الأمان والامتثال (خاصة في القطاع الطبي):

### 1. نمط انتحال الهوية المحكوم (Controlled Impersonation / "View As")

بدلاً من إنشاء حسابات جديدة، يمنح هذا النمط حسابك كـ **Super Admin** القدرة على إصدار جلسة مؤقتة (Scoped JWT Token) تتقمص دور أي مستخدم موجود أو كيان تجريبي مخصص للاختبار، مع بقاء هويتك الأصلية مسجلة في الخلفية.

* **آلية العمل في .NET Web API:**
* عند طلب التبديل إلى حساب طبيب أو صيدلية أو شركة أدوية، يتحقق السيرفر أولاً من أن المستخدم الحالي يملك صلاحية `PlatformAdmin` ويمر عبر التحقق الثنائي (MFA).
* يصدر السيرفر `JWT` يحتوي على `sub` (معرّف الحساب المستهدف) بالإضافة إلى Claim إضافي مثل `act` (Actor / Original Admin ID) و `is_impersonated = true`، وبمدة صلاحية قصيرة جداً (15–30 دقيقة).
* **وضع القراءة فقط (Read-Only Guard):** في طبقة الـ Middleware أو الـ Application Layer، يمكنك تفعيل وضع `ImpersonationReadOnly` بحيث يسمح بتصفح كافة الشاشات والـ Dashboards وفحص الأداء وسرعة الاستجابة، ويمنع أو يوقف أي عمليات كتابة (`POST/PUT/DELETE`) على الحسابات الحقيقية للمستخدمين.



---

### 2. الكيان المعزول للاختبار (Dedicated Sandbox / Demo Tenant)

لاختبار العمليات التي تتطلب كتابة وتفاعلاً فعلياً—مثل **مسح QR Code لبرنامج دعم مرضى (PSP)** أو إرسال إشعارات أو إنشاء طلب صيدلية—دون التأثير على تقارير شركات الأدوية أو مخزون الصيدليات الحقيقية:

* **إضافة حقل `IsTestEntity` (أو `TenantType = Sandbox`):** في جداول الكيانات الأساسية (`Organizations`, `Users`, `PspPrograms`)، يُضاف عمود منطقي `IsTest` (قيمته الافتراضية `false`).
* **تصفية التقارير والإحصائيات تلقائياً (Global Query Filters في EF Core):** داخل `DbContext`، يتم تطبيق فلتر عام يستثني تلقائياً أي سجلات مرتبطة بـ `IsTest == true` من كافة تقارير المبيعات، لوحات تحكم شركات الأدوية، والفوترة.
* **ميزة هذا النهج:** تمتلك المنصة عيادة واحدة وصيدلية واحدة وشركة أدوية واحدة وبرنامج PSP واحد بعلامة `IsTest = true` على بيئة الإنتاج نفسها. تظل هذه الكيانات غير مرئية تماماً للمستخدمين الحقيقيين أو لتقارير الإدارة، بينما تستطيع أنت كمسؤول الدخول عليها وفحص دورة العمل الكاملة (End-to-End) بما في ذلك مسح الـ QR Code.

---

### 3. مفاتيح التبديل الديناميكية (Feature Flags & Canary Testing)

لفحص أي تحديث جديد للتطبيق على الإنتاج قبل تعميمه على باقي المستخدمين، تُستخدم مكتبات مثل `Microsoft.FeatureManagement` لربط الميزات الجديدة أو مسارات التتبع (Telemetry) بمعرّف حسابك كـ Admin فقط. بهذه الطريقة، يعمل التطبيق على الإنتاج بالبيانات الحقيقية، لكن الميزات الجديدة أو وضع التشخيص المتقدم يظهر لحسابك أنت فقط.

---

### ضوابط الأمان والامتثال الطبي (Audit & Privacy)

بما أن المنصة تتعامل مع بيانات طبية ومرضى، فإن تطبيق "الماستر كي" يتطلب 3 ضوابط صارمة لضمان الحوكمة:

1. **سجل تدقيق غير قابل للتعديل (Immutable Audit Log):** تسجيل كل جلسة انتحال هوية تلقائياً (من قام بالدخول، متى، وعلى أي حساب، وماذا تصفح) لحماية الإدارة قانونياً وإدارياً.
2. **إخفاء البيانات الحساسة (PII Masking):** عند تصفح حساب طبيب أو صيدلية حقيقية بوضع الفحص، يُنصح بإخفاء أرقام هواتف المرضى أو بياناتهم الشخصية (مثل عرض `010****1234`) ما لم يكن الحساب تابعاً لكيان الاختبار `IsTest = true`.
3. **شريط تنبيه بصري في الواجهة:** إظهار شريط علوي واضح داخل التطبيق عند تفعيل الجلسة (مثل: *"وضع الفحص الإداري — التعديلات معطلة"*) لتجنب أي التباس أثناء العمل.

بهذا الدمج بين **Impersonation للقراءة والفحص** و **كيان واحد معزول بـ `IsTest` لاختبارات الـ QR Code والتفاعل**، يمكنك اختبار كل تحديث جديد على بيئة الإنتاج في دقائق معدودة وبأمان تام دون الحاجة لتعديل الكود أو بناء نسخ خاصة للاختبار.
